# Handy Spike: замеры Whisper на iPhone

Одноразовый прототип. Цель: узнать на iPhone 15 Pro Max, тянет ли он Whisper Turbo (1,5 ГБ) на Metal и на CPU, в том числе когда приложение в фоне. Это не продукт: нет клавиатуры, словаря, тем и локализации.

Что внутри:

- `core/` — Rust-крейт `handy_spike_core` (C ABI поверх `transcribe-cpp`, тот же движок, что на десктопе). Модель и сессия работают прямо в процессе приложения.
- `App/` — SwiftUI-приложение: скачивание моделей, запись с микрофона, распознавание, журнал замеров.
- `build-core.sh` — собирает ядро под iPhone и генерирует проект Xcode.
- `project.yml` — описание проекта для XcodeGen.

## Что установить (один раз)

1. **Xcode** из App Store (нужен iOS 17 SDK и выше). Запустите его один раз и примите лицензию.
2. Выберите Xcode как активный: `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.
3. Инструменты:

   ```bash
   brew install cmake xcodegen
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh   # затем откройте новый терминал
   ```

4. **iPhone** с iOS 17 или новее, кабель. На телефоне включите режим разработчика: Настройки → Конфиденциальность и безопасность → Режим разработчика (телефон перезагрузится). При первом подключении нажмите «Доверять» на iPhone и на Mac.

## Сборка

Из любой папки (скрипт сам найдёт свой каталог):

```bash
bash /путь/к/HandyRU/ios/spike/build-core.sh
```

Скрипт проверяет инструменты (и подсказывает `brew install ...`), ставит цель `aarch64-apple-ios`, собирает ядро с Metal, кладёт `libhandy_spike_core.a` в `ios/spike/lib/` и запускает `xcodegen generate`. Первый раз долго (компилируется ggml): от нескольких минут до четверти часа.

## Установка на iPhone

1. `open /путь/к/HandyRU/ios/spike/HandySpike.xcodeproj`
2. В Xcode: слева проект **HandySpike** → target **HandySpike** → **Signing & Capabilities** → **Team**: выберите свою команду (подойдёт и личный Apple ID). Если Xcode пишет, что идентификатор `com.handyru.spike` занят, поменяйте Bundle Identifier на любой свой.
3. Вверху выберите свой iPhone (не симулятор) и нажмите Run (Cmd+R).
4. Если на iPhone пишет «Недоверенный разработчик»: Настройки → Основные → VPN и управление устройством → ваш Apple ID → «Доверять», затем запустите приложение снова.
5. **Важно:** после первой установки остановите запуск в Xcode (Cmd+.) и открывайте приложение **с иконки на iPhone**. Под отладчиком система ведёт себя иначе (в фоне процесс не усыпляется и не убивается), и замеры фона будут неправдой.

Если Xcode ругается на возможность «Increased Memory Limit» (бывает с бесплатным личным Apple ID): удалите из `project.yml` блок `entitlements:` (3 строки с `com.apple.developer.kernel.increased-memory-limit`) и выполните в папке `ios/spike`: `xcodegen generate`. Тогда лимит памяти будет стандартным, и это надо указать в отчёте.

Журнал лежит в `Documents/spike-log.txt` и виден в приложении «Файлы» (На iPhone → Handy Spike), даже если приложение аварийно завершилось.

## Порядок замеров

Ставьте iPhone на зарядку и подключайте к Wi-Fi. Экран во время замеров не гаснет (автоблокировка отключена). Для всех прогонов одна и та же фраза 15–20 секунд на русском, говорить лучше в тихой комнате. Результат каждого прогона — строка в журнале.

**Подготовка.** Выберите **Turbo** → «Скачать» (1,5 ГБ, не сворачивайте приложение, пока идёт скачивание; sha256 проверяется автоматически).

**(a) Turbo + Metal, передний план.**
Переключатель «Metal» включён → «Загрузить модель» → «Запись» → скажите фразу → «Стоп и распознать».

**(b) Turbo + CPU, то же аудио.**
Выключите переключатель «Metal» → «Загрузить модель» (она загрузится заново на CPU) → «Повторить на последней записи». Аудио то же, что в (a).

**(c) Turbo + Metal, фоновый тест.**
Включите «Metal» → «Загрузить модель» → «Фоновый тест (20 с)». Сразу сверните приложение на домашний экран (свайп вверх, **не блокируйте экран**) и говорите фразу примерно 15 секунд. Через 20 секунд приложение само заберёт запись и начнёт распознавание в фоне. Подождите ещё минуту-две, затем откройте приложение и посмотрите журнал. Если приложение закрыто системой, откройте его снова: в журнале появится строка «предыдущий запуск оборвался», а перед ней будет последняя запись «старт».

**(d) Turbo + CPU, фоновый тест.**
Выключите «Metal» → «Загрузить модель» → «Фоновый тест (20 с)», как в (c).

**(e) То же для Small**, если Turbo не прошла (не загрузилась, приложение убито, RTF сильно выше 1). Выберите **Small**, скачайте и повторите (a)–(d).

Как читать строку журнала: `RTF` — время распознавания, делённое на длительность аудио (меньше 1 — быстрее реального времени). `footprint пик` — пиковая память процесса; `доступно` — сколько ещё можно занять до лимита системы; `состояние начало/конец` — `active` или `background`; `thermal` — нагрев (`nominal`, `fair`, `serious`, `critical`).

## Что прислать обратно

1. Кнопка «Скопировать журнал» и вставить текст целиком в сообщение (или файл `spike-log.txt` из приложения «Файлы»).
2. Модель iPhone и версия iOS.
3. Если приложение вылетело: что делали в этот момент (какой пункт a–e) и журнал после повторного запуска.

## Как выбирается CPU и GPU

Через запрос бэкенда при загрузке модели (`ModelOptions.backend` в `transcribe-cpp`), без выбора отдельного устройства:

- переключатель **Metal** включён: `Backend::Metal` (строго Metal, без тихого отката на CPU; если Metal недоступен, загрузка вернёт ошибку);
- выключен: `Backend::CpuAccel` (CPU плюс аппаратные ускорители памяти, если они есть): в фоне GPU может быть недоступен, поэтому важна лучшая скорость без него.

Режим «Авто» (`Backend::Auto`) не используется: нужно знать, что именно измерялось. Реально используемый бэкенд запрашивается у ядра после загрузки и пишется в журнал.

Язык распознавания фиксирован: `ru`. Остальные параметры запуска такие же, как у десктопа (по умолчанию, меняются только язык и задача), словарь не передаётся. Версия `transcribe-cpp` закреплена в `core/Cargo.lock` (0.4.1); у десктопа в `src-tauri/Cargo.lock` сейчас 0.4.0.

## Если сборка упала

- **`build-core.sh`**: пришлите последние ~80 строк вывода, а также вывод команд `xcodebuild -version`, `rustc -V`, `cmake --version`.
- **`xcodegen generate`**: пришлите его вывод целиком.
- **Xcode, ошибка линковки** (`Undefined symbols for architecture arm64`): пришлите первые ~20 строк списка символов и строку «Системные библиотеки Rust» из вывода `build-core.sh` (если её нет, выполните скрипт снова и найдите в выводе `native-static-libs`).
- **Xcode, ошибка подписи**: пришлите текст ошибки из Issue navigator (вкладка с красным значком слева).
- **Swift не компилируется** (прототип писался без доступа к компилятору Swift): пришлите файл и строку из ошибки вместе с её текстом.
