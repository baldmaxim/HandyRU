# Handy для iPhone: первая версия

Приложение диктовки на русском для iPhone (iOS 17+, проверялось на iPhone 15 Pro Max). Распознавание локальное, без сети: Whisper Turbo через Core ML на Neural Engine (632 МБ).

Что умеет сейчас:

- модель скачивается один раз и сама загружается при запуске;
- запись на открытом приложении с индикатором уровня, текст копируется одной кнопкой;
- фоновая диктовка: из любого приложения по AssistiveTouch, готовый текст остаётся в буфере для «Вставить»;
- фоновый режим включается сам при открытии приложения и выключается после 2 часов без диктовки;
- Revit и Renga пишутся латиницей (таблица замен в `App/TermDictionary.swift`, можно дополнять);
- тишина не распознаётся: вместо выдуманного текста «Речи не слышно»;
- настройки движка, контрольные проверки, последний замер и журнал свёрнуты в «Настройки и диагностика».

## Сборка и выпуск

1. `git pull`, затем `bash ios/spike/build-core.sh`, затем открыть `HandySpike.xcodeproj`.
2. После каждой генерации проекта выбрать команду (Team) на ДВУХ таргетах: **HandySpike** и **HandyDictationWidget**.
3. Проверить, что `PrivacyInfo.xcprivacy` один раз входит в Copy Bundle Resources таргета HandySpike.
4. Прямая установка: Product → Run с конфигурацией Release.
5. TestFlight (только платный Apple Developer Program): Product → Archive → Distribute App → TestFlight Internal Only. Внутреннее тестирование идёт без ревью, сборка живёт 90 дней. Для каждой новой загрузки увеличить `CURRENT_PROJECT_VERSION` в `project.yml`.
6. «Personal Team» (бесплатная) не может загружать в TestFlight, её сборки работают 7 дней.
7. После каждой установки или обновления первая подготовка модели занимает около 3,5 минуты при открытом приложении; потом около 2 с.

## Проверка перед выпуском

1. Запуск: модель готова сама; экран гаснет по обычному таймеру.
2. Запись на открытом приложении и индикатор уровня.
3. Revit и Renga в тексте латиницей.
4. Тишина 10 с: «Речи не слышно».
5. Фон: включить, перейти в Заметки, AssistiveTouch ×2, «Вставить».
6. Микрофон: одна и та же фраза при закрытом и при открытом Device Hub на Mac, то же подключение к Mac; в журнале искать строку «нулевой сигнал микрофона».
7. Звонок во время записи: распознаётся то, что записано.
8. Закрыть приложение и открыть: фоновый режим включился сам, текст на месте.
9. Отказ в микрофоне: кнопка «Открыть настройки».

## История замеров

Что внутри:

- `core/` — Rust-крейт `handy_spike_core` (C ABI поверх `transcribe-cpp`, тот же движок, что на десктопе). Модель и сессия работают прямо в процессе приложения.
- `App/` — SwiftUI-приложение: скачивание моделей, запись с микрофона, распознавание, журнал замеров.
- `build-core.sh` — собирает ядро под iPhone и генерирует проект Xcode.
- `project.yml` — описание проекта для XcodeGen.
- `icon/handyspike-icon.svg` — исходник иконки приложения; PNG лежит в `App/Assets.xcassets/AppIcon.appiconset`.

## Что установить (один раз)

1. **Xcode** из App Store (нужен iOS 17 SDK и выше). Запустите его один раз и примите лицензию.
2. Выберите Xcode как активный: `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.
3. Инструменты:

   ```bash
   brew install cmake xcodegen
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh   # затем откройте новый терминал
   ```

4. **iPhone** с iOS 17 или новее, кабель. На телефоне включите режим разработчика: Настройки → Конфиденциальность и безопасность → Режим разработчика (телефон перезагрузится). При первом подключении нажмите «Доверять» на iPhone и на Mac.

## Сборка

Из любой папки (скрипт сам найдёт свой каталог):

```bash
bash /путь/к/HandyRU/ios/spike/build-core.sh
```

Скрипт проверяет инструменты (и подсказывает `brew install ...`), ставит цель `aarch64-apple-ios`, собирает ядро с Metal, кладёт `libhandy_spike_core.a` в `ios/spike/lib/` и запускает `xcodegen generate`. Первый раз долго (компилируется ggml): от нескольких минут до четверти часа.

## Установка на iPhone

1. `open /путь/к/HandyRU/ios/spike/HandySpike.xcodeproj`
2. В Xcode: слева проект **HandySpike** → target **HandySpike** → **Signing & Capabilities** → **Team**: выберите свою команду (подойдёт и личный Apple ID). Если Xcode пишет, что идентификатор `com.handyru.spike` занят, поменяйте Bundle Identifier на любой свой.
3. Вверху выберите свой iPhone (не симулятор) и нажмите Run (Cmd+R).
4. Если на iPhone пишет «Недоверенный разработчик»: Настройки → Основные → VPN и управление устройством → ваш Apple ID → «Доверять», затем запустите приложение снова.
5. **Важно:** после первой установки остановите запуск в Xcode (Cmd+.) и открывайте приложение **с иконки на iPhone**. Под отладчиком система ведёт себя иначе (в фоне процесс не усыпляется и не убивается), и замеры фона будут неправдой.

Если Xcode ругается на возможность «Increased Memory Limit» (бывает с бесплатным личным Apple ID): удалите из `project.yml` блок `entitlements:` (3 строки с `com.apple.developer.kernel.increased-memory-limit`) и выполните в папке `ios/spike`: `xcodegen generate`. Тогда лимит памяти будет стандартным, и это надо указать в отчёте.

Журнал лежит в `Documents/spike-log.txt` и виден в приложении «Файлы» (На iPhone → Handy), даже если приложение аварийно завершилось.

## Порядок замеров

Ставьте iPhone на зарядку и подключайте к Wi-Fi. Экран во время замеров не гаснет (автоблокировка отключена). Для всех прогонов одна и та же фраза 15–20 секунд на русском, говорить лучше в тихой комнате. Результат каждого прогона — строка в журнале. Переключателя «Metal» больше нет: в шагах ниже выбирайте в списке «Бэкенд» пункт «Metal» или «CPU».

**Подготовка.** Выберите **Turbo** → «Скачать» (1,5 ГБ, не сворачивайте приложение, пока идёт скачивание; sha256 проверяется автоматически).

**(a) Turbo + Metal, передний план.**
Переключатель «Metal» включён → «Загрузить модель» → «Запись» → скажите фразу → «Стоп и распознать».

**(b) Turbo + CPU, то же аудио.**
Выключите переключатель «Metal» → «Загрузить модель» (она загрузится заново на CPU) → «Повторить на последней записи». Аудио то же, что в (a).

**(c) Turbo + Metal, фоновый тест.**
Включите «Metal» → «Загрузить модель» → «Фоновый тест (20 с)». Сразу сверните приложение на домашний экран (свайп вверх, **не блокируйте экран**) и говорите фразу примерно 15 секунд. Через 20 секунд приложение само заберёт запись и начнёт распознавание в фоне. Подождите ещё минуту-две, затем откройте приложение и посмотрите журнал. Если приложение закрыто системой, откройте его снова: в журнале появится строка «предыдущий запуск оборвался», а перед ней будет последняя запись «старт».

**(d) Turbo + CPU, фоновый тест.**
Выключите «Metal» → «Загрузить модель» → «Фоновый тест (20 с)», как в (c).

**(e) То же для Small**, если Turbo не прошла (не загрузилась, приложение убито, RTF сильно выше 1). Выберите **Small**, скачайте и повторите (a)–(d).

Как читать строку журнала: `RTF` — время распознавания, делённое на длительность аудио (меньше 1 — быстрее реального времени). `footprint пик` — пиковая память процесса; `доступно` — сколько ещё можно занять до лимита системы; `состояние начало/конец` — `active` или `background`; `thermal` — нагрев (`nominal`, `fair`, `serious`, `critical`).

## Замер Core ML (Neural Engine)

Turbo через Core ML (WhisperKit 1.1.1, модель `openai_whisper-large-v3-v20240930_turbo_632MB`, 632 МБ). Цель: сколько занимает Turbo на Neural Engine и работает ли он, когда приложение в фоне (iPhone 15 Pro Max, iOS 27.2).

**Обновление и сборка.** `git pull`, затем `bash ios/spike/build-core.sh`. Пакет WhisperKit Xcode подтянет сам при открытии проекта (нужен интернет).

**Подпись.** Разрешение `com.apple.developer.background-tasks.continued-processing.inference` в проект не входит: Apple отклонила его при подписи. На iPhone 15 Pro Max с iOS 27.2 Neural Engine работал в фоне и без него, при включённой записи звука. Это расходится с документацией Apple и может измениться с обновлением iOS.

**Запуск** с иконки на iPhone, не под отладчиком (как и для остальных замеров).

**Скачивание и загрузку для замеров делайте при открытом приложении.** Долгий запуск локализован в `MLModel.load` готового `AudioEncoder.mlmodelc`; отдельного вызова `compileModel` нет. Внутри Core ML возможна специализация под устройство. Само длительное ожидание не доказывает промах кэша. `prewarm=false` исключает дополнительный цикл load–unload–load. В WhisperKit 1.1.1 проверен `loadTokenizerIfNeeded`: он ищет локальные файлы и при необходимости обращается к загрузчику токенизатора. `download=false` относится к моделям, а не гарантирует отсутствие сетевой загрузки токенизатора.

**Прогоны.** Приложение между шагами не перезапускайте: последняя запись хранится только в памяти. Фоновый тест пишет новую запись, поэтому пп. 3–4 идут на записи из п. 2. Говорите фразу с Revit, Renga и другими вашими терминами и пришлите её дословно.

1. Бэкенд «Core ML: Neural Engine» → «Скачать» → «Загрузить модель» (приложение открыто) → «Запись» → фраза 15–20 с → «Стоп и распознать».
2. «Фоновый тест (20 с)» на том же бэкенде: сразу сверните приложение, откройте Заметки, говорите, не возвращайтесь минимум 30 с. Затем откройте приложение и посмотрите журнал.
3. Бэкенд «Core ML: CPU» → «Загрузить модель» → «Повторить на последней записи». Это контроль скорости без Neural Engine.
4. Бэкенд «CPU», модель Turbo → «Загрузить модель» → «Повторить на последней записи». Это сравнение точности с файлом на 1,5 ГБ.
5. «Core ML: CPU» → «Загрузить модель» → «Фоновый тест (20 с)», как в п. 2.

**Как читать журнал.** В строке «конец» перед `текст=` стоят `энкодер=… с декодер=… с откаты=…`:

- `энкодер` в фоне примерно как в открытом приложении (п. 1): скорость сохраняется; это косвенный признак использования ускорителя;
- `энкодер` в фоне примерно как на «Core ML: CPU» (п. 3): возможен откат на CPU; для доказательства нужен compute plan или профиль устройства;
- `ОШИБКА`: доступа к Neural Engine в фоне нет.

Проверьте `состояние начало` и `конец` у фоновых прогонов: должно быть `background`, иначе замер не фоновый.

## Диктовка через AssistiveTouch

Чтобы оставаться в мессенджере, откройте Handy: модель Neural Engine или CPU
загружается сама, а переключатель **«Фоновая диктовка»** включается автоматически,
если вы включали его раньше (или включите его вручную). Микрофон остаётся активным
до выключения режима; между фразами звук отбрасывается. Состояние отображается
в Live Activity / Dynamic Island. Metal для этого режима не поддерживается.
После 2 часов без диктовки режим выключается сам и включается снова при открытии
приложения.

В «Командах» создайте команду из следующих действий:

1. **Handy → «Диктовка в фоне»**.
2. **Если** результат «Диктовки в фоне» **есть любое значение**.
3. Внутри условия — **«Скопировать в буфер обмена»**, вход: результат действия
   **«Диктовка в фоне»**.
4. Закончить условие. Ветка «Иначе» не нужна.

В настройках iPhone: **Универсальный доступ → Касание → AssistiveTouch →
Одно касание → Быстрые команды** выберите созданную команду. Первое нажатие
плавающей кнопки начинает фразу, повторное останавливает и распознаёт её, оставаясь
в текущем приложении. После этого нажмите «Вставить». При начале записи и пустом
результате буфер сохраняется. Если микрофон прерван звонком или другим приложением,
режим выключается; откройте Handy, и он включится снова.

Проверка на устройстве: включить режим → перейти в другое приложение → нажать
AssistiveTouch → произнести фразу → нажать ещё раз → вставить текст. В журнале
обе команды и распознавание должны иметь состояние `background`. После выключения
режима микрофон должен освободиться.

Прежняя ссылка `handyspike://dictation/toggle` тоже доступна, но **открывает Handy**.
Она предназначена для запуска без заранее включённого фонового режима. Выбранные
модель и способ распознавания сохраняются между запусками.

## Что прислать обратно

1. Кнопка «Скопировать журнал» и вставить текст целиком в сообщение (или файл `spike-log.txt` из приложения «Файлы»).
2. Модель iPhone и версия iOS.
3. Если приложение вылетело: что делали в этот момент (какой пункт a–e) и журнал после повторного запуска.

## Как выбирается CPU и GPU

Через запрос бэкенда при загрузке модели (`ModelOptions.backend` в `transcribe-cpp`), без выбора отдельного устройства:

- переключатель **Metal** включён: `Backend::Metal` (строго Metal, без тихого отката на CPU; если Metal недоступен, загрузка вернёт ошибку);
- выключен: `Backend::CpuAccel` (CPU плюс аппаратные ускорители памяти, если они есть): в фоне GPU может быть недоступен, поэтому важна лучшая скорость без него.

Режим «Авто» (`Backend::Auto`) не используется: нужно знать, что именно измерялось. Реально используемый бэкенд запрашивается у ядра после загрузки и пишется в журнал.

Язык распознавания фиксирован: `ru`. Остальные параметры запуска такие же, как у десктопа (по умолчанию, меняются только язык и задача), словарь не передаётся. Версия `transcribe-cpp` закреплена в `core/Cargo.lock` (0.4.1); у десктопа в `src-tauri/Cargo.lock` сейчас 0.4.0.

## Если сборка упала

- **`build-core.sh`**: пришлите последние ~80 строк вывода, а также вывод команд `xcodebuild -version`, `rustc -V`, `cmake --version`.
- **`xcodegen generate`**: пришлите его вывод целиком.
- **Xcode, ошибка линковки** (`Undefined symbols for architecture arm64`): пришлите первые ~20 строк списка символов и строку «Системные библиотеки Rust» из вывода `build-core.sh` (если её нет, выполните скрипт снова и найдите в выводе `native-static-libs`).
- **Xcode, ошибка подписи**: пришлите текст ошибки из Issue navigator (вкладка с красным значком слева).
- **Swift не компилируется** (прототип писался без доступа к компилятору Swift): пришлите файл и строку из ошибки вместе с её текстом.

## Интерфейс и диагностика загрузки (2 ноября 2026)

Верхняя карточка содержит название, скачивание, подготовку, прогресс и ошибки
модели. Готовая модель — вся строка зелёная, без повторного статуса. Значки ↻ и ⏏
имеют область нажатия 44 × 44 pt. Удаление — только свайпом влево с подтверждением.
Запись и текст находятся выше фонового режима; настройки бэкенда, повтор записи,
фоновый тест и журнал свёрнуты в «Настройки и диагностика». RTF и шкала задержки
раскрываются под текстом. Автоматической остановки обычной диктовки нет.

Live Activity объясняет каждое действие: начать → нажать ещё раз для остановки →
дождаться завершения Shortcut «Handy» и вручную вставить. Приложение не может
подтвердить, что внешний шаг Shortcut уже скопировал результат, поэтому Activity
сообщает «Текст готов», а не «Скопирован». Пустой результат предлагает повторить
запись. После запуска завершаются Activity предыдущего процесса; новый фоновый
режим ждёт этой очистки и остаётся выключенным до действия пользователя.

Замеры содержат идентификатор прогона, абсолютный путь и его совпадение с прошлым,
версию ОС, compute units, параметры WhisperKit, время создания WhisperKit без
моделей, прямое время `AudioEncoder MLModel.load`, итоги `loadModels` и heartbeat
каждые 10 секунд (состояние приложения и thermal). Отпечатки файлов включают имена,
размеры и mtime — это не SHA256 содержимого весов. Их сбор не читает 632 МБ перед
тестом и не прогревает файловый кэш весов. `cacheHit=unknown` указан намеренно.

Параллельный вариант запускает единственный `MLModel.load` энкодера одновременно
со штатной загрузкой MelSpectrogram и TextDecoder. Сами модели, compute units и
декодирование не меняются. В диагностике доступен последовательный контрольный
вариант. Тайминг `ожидание энкодера в loadModels` при параллельной загрузке отражает
только оставшееся ожидание, полное время MLModel.load записано отдельно. Ошибка
декодера дожидается завершения/отмены предварительной загрузки и освобождает модели.

Проверенные факты исходного последовательного прогона после обновления:

- iPhone 15 Pro Max, iOS 27.2 (24B119), Release, весь замер `active`.
- Общая загрузка 210,94 с; непосредственно `AudioEncoder MLModel.load` 201,846 с;
  декодер 8,516 с; токенизатор 0,490 с; создание WhisperKit 0,001 с.
- Видимые записи `Library/Caches/com.handyru.spike/com.apple.e5rt.e5bundlecache`
  сохранились после установки обновления (257 элементов до/после, без удаления).
  Во время загрузки появились новые `.bundle`, ANE/BNNS и `.milhash` записи.
- Это свидетельствует о создании новых артефактов Core ML, но не устанавливает,
  почему прежние записи не использованы. Причина смены ключа кэша пока не доказана.
- Instruments `xctrace` видит iPhone, но не смог прикрепиться к Handy ни по имени,
  ни по PID из `devicectl`; трассы «prepare and cache» пока нет.

Apple описывает привязку специализации к пути и конфигурации и проверку через
Core ML Instrument в [WWDC23: Improve Core ML integration with async prediction](https://developer.apple.com/videos/play/wwdc2023/10049/).
Наличие кэша и быстрый второй запуск сами по себе не заменяют эту проверку.

Дополнительные результаты проверки:

- Повторная последовательная загрузка в том же процессе: 2,011 с,
  `AudioEncoder MLModel.load` 1,282 с, декодер 0,301 с, токенизатор 0,417 с.
  Путь и все три отпечатка метаданных совпали.
- После следующей установки обновления UUID контейнера изменился, а отпечатки
  файлов остались прежними. Смена абсолютного пути — проверенное наблюдение;
  её причинная связь с промахом кэша пока остаётся гипотезой.
- При перезапуске с включённой фоновой диктовкой журнал подтвердил завершение
  **одной** старой Live Activity и выключенное состояние фонового режима.

В параллельном прогоне приложение ушло в фон, thermal достиг serious;
320,83 с не подходят для сравнения с последовательной загрузкой на переднем плане.
Поэтому по умолчанию используется последовательная загрузка. В итоговой строке
журнала `foregroundRun=false` исключает замер с потерей активного состояния.

### Диагностика повторяющегося «Продолжение следует…»

Скорость 0,55–0,59 с энкодера не подтверждает правильность распознавания.
Пользователь сообщил одинаковый результат на реальной речи. Для разделения
ошибок захвата и распознавания добавлены замеры raw-пика, числа входных сэмплов,
ошибок/пустых выходов конвертера, а также peak/RMS/dBFS/доли ненулевых сэмплов
после преобразования в 16 кГц и маршрут микрофона. Аудио пользователя на диск
не записывается и никуда не отправляется.

«Настройки и диагностика → Проверить распознавание без микрофона» подаёт
в выбранный движок встроенный PCM WAV (16 кГц mono). Он синтезирован локальным
голосом macOS Milena, не содержит пользовательской речи. Ожидаемая фраза:
«Проверка распознавания речи. Завтра в десять утра мы обсудим новый проект
и подготовим список задач». Кнопка не активирует микрофон и не заменяет
последнюю пользовательскую запись для повторных сравнений бэкендов.

На iPhone 15 Pro Max 3 ноября контрольный WAV дважды дал ожидаемый текст
за 1,01 и 0,97 с. В отдельной записи со встроенного микрофона все 168 000
исходных отсчётов были нулевыми. После преобразования в 16 кГц все 55 330
отсчётов также были нулевыми, ошибок конвертера не было. Именно на этой
записи модель выдала «Продолжение следует…». Причина нулей на входе iOS
пока не установлена. Прототип теперь пропускает распознавание полностью
нулевой записи и показывает сообщение о микрофоне.
